# Understanding the Minnow Codebase - A Beginner's Guide

## What is This Project?

This is **Stanford CS144 Networking Lab** - a project where you'll build a TCP/IP networking stack from scratch. The project is called "minnow" and teaches you how networking protocols work at a fundamental level.

## Project Structure Overview

```
minnow/
├── src/           # Your implementation code (what you'll write)
├── util/          # Utility classes provided by the course (sockets, parsers, etc.)
├── tests/         # Test files to verify your implementation
├── apps/          # Application programs (like webget, tcp_native)
└── build/         # Compiled output (generated by CMake)
```

## Learning Path: How to Understand This Codebase

### Step 1: Start with the Basics - ByteStream

**Location:** `src/byte_stream.hh` and `src/byte_stream.cc`

**What it is:** A fundamental data structure that acts like a queue with a fixed capacity. Think of it as a pipe where:
- **Writer** pushes data into one end
- **Reader** pops data from the other end
- It has a maximum capacity (like a buffer)

**Key Concepts:**
- `Writer::push()` - Add data to the stream
- `Reader::peek()` - Look at data without removing it
- `Reader::pop()` - Remove data from the stream
- `capacity_` - Maximum bytes the stream can hold

**How to learn:**
1. Read `src/byte_stream.hh` - understand the interface
2. Look at `tests/byte_stream_basics.cc` - see how it's tested
3. Try implementing `src/byte_stream.cc` (currently has placeholder code)

### Step 2: Understand the Reassembler

**Location:** `src/reassembler.hh` and `src/reassembler.cc`

**What it is:** Handles out-of-order data packets. In networking, packets can arrive in any order, and the Reassembler puts them back in the correct sequence.

**Key Concepts:**
- `insert()` - Takes a substring with an index and reassembles it
- Handles overlapping data
- Handles gaps (missing data)
- Writes to a ByteStream when data is ready

**Why it matters:** This is how TCP handles out-of-order packets!

### Step 3: Explore the Utility Library

**Location:** `util/` directory

**What it provides:**
- **Socket classes** (`socket.hh`) - Wrappers around system sockets
- **Address handling** (`address.hh`) - IP addresses and ports
- **Network headers** (`ethernet_header.hh`, `ipv4_header.hh`) - Protocol headers
- **Parsers** (`parser.hh`) - Parse network packets

**How to learn:**
- These are mostly provided code - you'll use them, not implement them
- Read the header files to understand what's available
- Look at `apps/webget.cc` to see how they're used

### Step 4: Study the Tests

**Location:** `tests/` directory

**Why tests are important:**
- Tests show you **exactly** what each component should do
- Tests are like documentation with examples
- Running tests tells you if your code works

**Test naming pattern:**
- `byte_stream_*.cc` - Tests for ByteStream
- `reassembler_*.cc` - Tests for Reassembler
- `send_*.cc` / `recv_*.cc` - Tests for TCP sender/receiver (later in course)

**How to use tests:**
```bash
# Build the project
cmake -S . -B build
cmake --build build

# Run specific tests
cmake --build build --target check0  # Checkpoint 0 tests
cmake --build build --target test    # All tests
```

### Step 5: Look at Example Applications

**Location:** `apps/` directory

**Examples:**
- `webget.cc` - Downloads a web page (like `wget`)
- `tcp_native.cc` - Uses the native TCP implementation
- `bidirectional_stream_copy.cc` - Copies data between streams

**How to learn:**
- These show how the networking stack is used in practice
- Read them after understanding the core components

## Key C++ Concepts You'll See

> **📘 Complete C++ Concepts Guide**: See `CPP_CONCEPTS_NEEDED.md` for a comprehensive list of all C++ concepts used in this codebase, organized by priority.

### Essential Concepts (Must Know)
- **Header Files (.hh) vs Implementation Files (.cc)**
  - `.hh files` - Declarations (what functions exist, their signatures)
  - `.cc files` - Implementations (how functions work)

- **Classes and Inheritance**
  ```cpp
  class Writer : public ByteStream  // Writer inherits from ByteStream
  class Reader : public ByteStream  // Reader also inherits from ByteStream
  ```

- **Modern C++ Features**
  - `std::string_view` - Lightweight string reference (no copying)
  - `uint64_t` - 64-bit unsigned integer
  - `std::move()` - Move semantics (efficient transfer)
  - `#pragma once` - Header guard (prevents multiple includes)

- **References and Const**
  - `Reader& reader()` - Returns a reference (no copy)
  - `const Reader& reader() const` - Const member function

### CMake Build System
- `CMakeLists.txt` - Build configuration
- You don't need to understand it deeply, just know:
  - `cmake -S . -B build` - Configure
  - `cmake --build build` - Compile


   - They show expected vs actual behavior

   - Step through code to see what's happening

## Common Patterns in This Codebase

### 1. Test Harness Pattern
Tests use "harness" classes that provide a fluent interface:
```cpp
test.execute( Push { "hello" } );
test.execute( Peek { "hello" } );
```

### 2. Capacity Management
Many classes have capacity limits - always check available space before adding data.

### 3. Error Handling
- `set_error()` - Mark something as having an error
- `has_error()` - Check if error occurred
